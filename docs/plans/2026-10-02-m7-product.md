# M7 — FrameLab 深色视频创作工作台

## 用户授权与设计

用户要求利用外部 Hypit 的本地测试视频实际制作成片，继续已有开发计划，并把 Qt 交互优化成产品。用户已选择深色创作工作台，此前授权直接实现、自由设计与提交迭代。本轮继续当前专用 `qt-video-workbench` 分支，保留已完成 M0–M6 的历史与发布物。

原创品牌 FrameLab / 灵感片场。布局采用主工具栏、左侧素材/组件/示例、中央预览与原生播放定位、右侧属性/提案、底部任务/日志。空状态提供创建、打开和示例入口；可编辑状态、后台启动状态、导入与导出状态决定按钮可用性。错误保留有效工程并提供反馈。仅经真实媒体验证的导出显示成功、允许播放成片。

本地示例从固定版本外部 Hypit 中发现，记录来源、哈希和真实 ffprobe/解码结果；不复制上游源码或媒体进本仓库。点击使用示例创建原创 `video-story` 工程，并将其复制为工程素材，再通过已有 Studio writer 将已登记素材绑定到可写视频字段。视频模板为 1280×720、30fps、8 秒，画面左侧文案、右侧完整呈现竖屏视频。原始音频静音。首版视频导入只接受可完整解码的 H.264 MP4、30fps、至少8秒、64MiB以内；取前8秒。限制在界面和文档中明确。

预览控制使用固定版本 Studio 真实 DOM：`.stage-scrubber` 的 input 驱动 store.seek，`[data-play]`、`[data-previous]`、`[data-next]` 驱动真实播放/逐帧。桥接只在预览可用时启用；异步回调使用 generation/QPointer 防止关闭、切换后更新旧页面。默认精简预览保留失败信息，允许切回完整 Studio。

## 实施边界

新增能力延续现有 qvw_domain/services/ui/controllers 分层。UI 不直接调用进程或编辑源文件，Studio 编译拒绝仍由已有编辑事务回滚。素材遵循受控路径、哈希、不覆盖他人文件；异步导入不得向已关闭或已切换的工程提交。无付费 Provider，无全局环境修改。既有测试回归，新产品集成测试单独运行；成功以真实输出和 ffmpeg 全片解码为准。发布更新单独目录，保留 M6 1.0.0。
