# Qt 视频工作台使用指南

## 平台与依赖

本次主平台为 macOS arm64，最低构建目标15.0；实际验收机15.7.7。应用包自带Qt6.11.2和WebEngine，模板、配置示例及第三方说明位于Contents/Resources。包采用本地ad hoc签名，未公证；Windows和另一台无Qt机器未验收。

视频执行使用外部Hypit0.2.10（固定commit `1af179d3f58284c2d6d3c1f63052172a4fe1b5a6`）、Node>=22.15、FFmpeg/ffprobe和Runtime选择的渲染浏览器。这些不在.app或ZIP内，首次安装应按固定Hypit版本的上游安装说明准备其依赖、pnpm10.33.0及本地hyperframes浏览器。开发机实际Node25.8.2、FFmpeg9.0.2；没有修改全局shell配置。

将准备好的Hypit Distribution放在.app同级的`hypit`目录（含bin/hypit.mjs及其依赖），或用“选择配置…”指定自己的版本锁。发布默认配置为Resources/config/version-lock.json；distributionPath按该config目录上一级(Resources)解析，`../../../hypit`就是.app的同级目录。显式配置的相对路径仍按其config目录上一级解析。

可选工具配置：

```json
{
  "hypit": {"version":"0.2.10","distributionPath":"runtime/hypit","launcher":"bin/hypit.mjs"},
  "tools": {"node":"/absolute/path/node","ffmpeg":"/absolute/path/ffmpeg","ffprobe":"/absolute/path/ffprobe","codex":"/absolute/path/codex"}
}
```

省略tools时，从本应用子进程PATH及macOS常用安装位置解析。仅影响应用进程，不改用户PATH。缺依赖或版本不符会在日志中显示原因。Qt运行库无需另行安装。

`hypit.launcher`可使用JS入口`bin/hypit.mjs`，也可使用固定版本官方shell入口`hypit`。JS入口由解析到的Node执行；shell入口默认直接执行并继承应用PATH。若官方shell同时配置了`tools.node`，应用核对固定脚本内容后用指定Node执行其相邻JS入口。自定义shell与显式Node组合无法保证实际Node选择时会给出错误，可改为JS入口。

`tools.ffmpeg`/`tools.ffprobe`指定工作台成片校验所用程序。Hypit Provider 的渲染/媒体程序由工程Runtime的endpoints config中的`ffmpegPath`/`ffprobePath`选择，缺省在子进程PATH中查找；需要固定其他媒体工具链时同时配置Runtime。这两层配置分别记录各自实际调用。

## 完整创作流程

1. 新建工程，选择名称和目录。工程包含本项目原创1280×720、30fps、8秒图片标题卡、源码与运行配置。
2. 导入PNG/JPEG；按内容解码、hash命名并复制到工程，原图不改。选择素材和组件，再点“应用到选中组件的图片”。导入与绑定是两个动作。
3. 右侧原生属性修改标题、主题色、副标题或入场帧数。编辑串行执行，后端回读确认才进入历史；可撤销/重做。外部冲突要求刷新，未知结果不自动重放。
4. 辅助「模拟提案」可输入`标题改为校园摄影社`、`主题色改为#e47735`或`图片使用第1张`。核对当前值、拟修改值及来源后确认；手动编辑、刷新、关闭或换工程会使提案失效。此入口保持模拟，主入口的真实模型用法见下方1.2节；外部JSON来源未核验。
5. 保存工程元数据。源码一直是视频内容的权威事实；单文件源码编辑只允许当前会话白名单，明确编译失败时经内容核对恢复。
6. 点击导出MP4。应用冻结本次输入，显示计划、源码版本、BuildID及阶段。完成Work后等待Result保存；精确Output获取、参数与全片解码全部通过才写到选择的目的地。
7. 停止观察保留后台Build；恢复观察查询同一任务。提交尚无ID时仅从独立Runtime查找唯一Build，无法确定时不重提。取消针对当前ID并核对终态。原工程后续编辑不会改变这次冻结成片。
8. 关闭再打开workbench.qvw.json继续编辑。可以搬移整个工程目录；历史导出任务的绝对工程根和目的地需要重新核对，不把旧成片视作新源码的导出。
9. “清理当前终态缓存”只处理已确认终态任务的自有冻结目录；活动、未知或被修改的任务拒绝删除。成片、工程输入与其他任务不删。停止观察不等于清理。

## 日志与诊断

任务面板显示错误原因；JSONL日志包含参数数组及退出码，单条有界并轮转。用户可用--log指定文件。多个实例写同一日志时共用跨进程锁；超过100毫秒的锁竞争会警告本条未保存，随后继续尝试，不永久停止日志。CLI退出、构建完成、Output获取和成片可解码分别验证，任何一层失败都不显示导出成功。

命令行无截图检查：

```bash
'QtVideoWorkbench.app/Contents/MacOS/qt-video-workbench' \
  --verify-startup --create-project '/absolute/path/校园 工程' \
  --report-out '/absolute/path/startup.json' --log '/absolute/path/workbench.jsonl'
```

也可用--project指定已有清单，--config指定外部配置。验证必须读到真实Snapshot、已编译预览和加载完成的图片，退出时清理自有Studio；非零退出及FAIL报告保留原因。验证完成前关闭窗口会返回退出码9和FAIL报告。不截图。

## FrameLab 1.1 — 使用本地视频创作

新增深色「FrameLab · 灵感片场」工作台。左侧为素材、组件、示例，中央为画面及原生播放定位，右侧为属性/提案，底部为导出任务/日志。

1. 在「示例」选择「对话故事 · 本地测试视频」，可先播放，再点「用此视频创作…」。指定工程名与保存目录，自动创建原创视频故事工程、校验并复制素材、通过真实编辑事务应用到组件。
2. 当前 Hypit 本机找到三个文件，内容哈希完全相同，因此界面合并为一个示例，提示中保留三个来源。外部分发缺少输出时会说明原因；也可新建工程后直接导入自己的视频。
3. 视频故事模板为1280×720、30fps、8秒；左侧文案、右侧完整显示竖屏画面。使用视频前8秒，**原始音频静音**。图片标题卡仍可在新建对话框中选择。
4. 首版视频导入限H.264 MP4、恒定30fps、至少8秒/240帧、64MiB以内、4000万像素以内。前240帧的实际时间戳必须从0开始并按30fps排列。媒体工具会完整校验视频流；失败或取消时不登记素材。校验期间可点「取消导入」。异步导入不覆盖源视频，也不修改Hypit。
5. 导入自己的视频后，在素材页选择素材、组件页选择含视频属性的组件，再点「应用到选中组件」。图片只能应用到图片组件；没有兼容选择时按钮禁用。属性页显示素材名称，实际受控相对路径可在提示或高级源码编辑中查看。
6. 中央「播放 / 暂停」、上一帧/下一帧和定位条驱动真实Studio画面。默认只显示画面；「完整Studio」打开其完整面板，「专注预览」收起Qt侧栏。完整Studio进入素材预览时原生逐帧控件禁用，返回画面后恢复。
7. 右上「导出MP4…」经本地构建、精确Output获取、参数检查与全片解码后才显示完成。渲染中进度为等待动画，不提供推测百分比。完成后「播放成片」打开本地播放器，「打开所在文件夹」打开保存目录。失败信息留在任务页；详细过程见运行日志。

工程或素材写入中不能切换工程；导出停止观察后可以切换或关闭当前工程，构建不会被当作取消，任务记录仍可恢复；关闭/切换取消旧导入，防止异步结果应用到其他工程。打开另一个工程失败时保留当前有效工程与属性。辅助模拟提案仍明确为本地模拟；1.2的主入口已接入真实模型。

## FrameLab 1.2 — Agent 创作

### 连接当前 Codex 登录

使用已安装的 Codex CLI，并先确认 `codex login status` 显示当前登录。本次真实验收使用 Codex0.159.2 的 ChatGPT 登录，不要求 API Key。CLI会自行使用当前登录，工作台不读取、显示或复制登录凭据。

若终端能运行 Codex，Finder 启动却提示无法启动，使用「选择配置…」加载含 `tools.codex` 绝对可执行路径的 JSON。可用终端 `command -v codex` 查看当前入口。应用只设置自己的程序路径和子进程环境，不修改全局PATH。模型请求有120秒超时；未登录、网络或输出错误会显示失败，不执行工程修改。

### 创建三段图片故事

1. 右侧默认打开「Agent 创作」。选择三张本地PNG/JPEG，缩略图来自本地，名称、尺寸和去重后的ID可供模型规划；图片像素留在本机。
2. 输入“创建15秒校园招新短片，竖屏，开场3秒、主体8秒、结尾4秒，结尾写周五晚七点欢迎加入”。首次能力为原创三段图片故事，无配音；模型不会猜测图片内容。
3. 点击生成并等待待审阅方案。卡片可编辑文案、图片、主题色、字号、时长及顺序；时长以30fps整数帧保存，每段1–30秒，总3–60秒。默认15秒。核对总时长和项目名后确认新的保存目录。
4. 确认会创建并切换到新工程，弹窗明确展示路径；现有工程目录不会被覆写。程序依次创建、导入、编译和填写真实属性，每次写入都回读确认。成功后可以手动修改、播放或导出。

### 继续修改、停止与恢复

- 组件页选中结尾，勾选「下一次请求仅当前组件」，输入“结尾标题改为周五一起玩！其他字段不要动”。方案显示实际字段ID、当前值和拟修改值，确认前源码不变。
- checkbox控制下一次请求；当前任务的批准范围单独显示。等待模型、执行、暂停或失败重试时切换组件只影响未来请求，原任务范围保持不变。取消限定后新请求以全工程为范围。素材、字段类型、范围或版本不合法的整份方案会被拒绝。
- Agent不是原子事务。「停止后续」保留已经确认的步骤，当前写入会完成回读。失败显示真实成功条数；同一源码指纹下可重试未完成步骤，每个失败步骤最多重试两次，成功前缀不重复执行。
- 「修订方案」会把真实错误和最新工程上下文交给模型，仍需重新审阅批准。「撤销上一步」使用手动编辑共用的历史，只回退一个实际已记录的修改。人工修改使旧批准失效。
- 工程的`.workbench/agent/current.json`保存任务，`events.jsonl`记录执行事实。重开读取真实源码/快照后才恢复：匹配时审阅剩余动作；过期或损坏时明确提示。不会恢复旧批准。搬移整个工程后旧任务的工程根身份不自动迁移。
- 导出必须由用户点击并选择路径；停止Agent后续步骤不取消已提交Build。导出页的停止观察、恢复观察与取消仍按精确Build ID执行。

版本区区分工程事实、编译快照、中央可视预览和最近导出。未取得实际预览确认时显示等待；媒体参数通过不等于创作文案或视觉效果得到人工认可。最近导出按源码指纹判断是否过期。

本轮真实三段作品位于`.workbench/deliverables-m8/`，启动入口为`.workbench/启动FrameLab.command`，会打开最新可编辑工程。新版运行包放在`.workbench/release-macos-arm64-1.2.0/`；1.0.0和1.1.0交付保留。macOS运行包仍依赖外部Hypit0.2.10、Node、FFmpeg/ffprobe及当前登录的Codex CLI，详见上文配置说明。


## FrameLab 1.3 创作流程与工作区

- **输入目标 → 审阅方案 → 执行 → 查看结果**：右侧只显示当前阶段相关操作。审阅卡片默认显示修改前后、影响组件和时间范围；点击“修改方案”编辑字段，再确认执行。“重新描述目标”会撤销旧方案的执行许可，保留输入供重写。
- **实际生成反馈**：显示 Codex CLI 实际送达的公开消息，任务详情可再次展开查看。某些 CLI 请求只在消息完成时发送文本，因此不会伪造逐字输出；完整方案通过验证之前不能执行。不展示模型的内部推理。
- **场景缩略条**：同一帧范围的组件合并为一个场景入口。图片素材可读时显示缩略图，否则显示名称卡片。点击会定位场景起点并选中精确组件，播放时高亮当前场景；左侧“组件”可进一步选中同场景的其他属性对象。
- **素材库**：工具栏支持批量选择 PNG/JPEG/MP4，也可将最多 64 个本地文件拖入素材列表。逐个校验、保存并报告结果；取消仅停止剩余导入，已完成的素材保留。图片须小于 64 MiB / 4000 万像素；视频继续要求 H.264、30 fps、至少 8 秒，模板使用前 8 秒且静音。
- **预览与替换**：双击素材放大预览图片或播放视频。选中一个素材和一个兼容组件后，点击“替换选中组件素材”；此操作走相同编辑事务，支持撤销。多选时禁用替换，防止误用素材。
- **缺失文件**：通过“打开工程”重新打开工程时，会提示定位缺失的登记素材。选择与原素材大小及 SHA-256 一致的原文件后，恢复原路径；不会用内容不同的文件冒充原素材。新内容应导入为新素材后执行替换。取消时保留当前打开的工程，已找回的原文件仍保留。
- **工作区**：关闭后记住窗口位置、面板尺寸、最近 12 个工程及每个工程的播放位置。重新打开后等待实际预览就绪再恢复位置，不会自动播放。用户主动点击场景会覆盖待恢复位置。
- **工作历史**：底部“工作历史”集中展示最多 200 条本机创作任务、已编译修改和导出记录。可查看详情、打开所属工程、播放已验证的成片或打开其文件夹。记录只用于查看，不恢复执行批准；当前工程任务恢复仍需按右侧提示重新审阅。

工作区记录保存在应用数据目录的 `workspace.json`；工程本身不依赖此文件。1.3 运行包位于 `.workbench/release-macos-arm64-1.3.0/`，新的实际验证工程和成片位于 `.workbench/deliverables-m11/`。以前交付保留。


## 1.4：查找与继续创作

- **素材查找**：左侧素材页支持名称搜索（不区分大小写）与图片/视频类型筛选。显示当前可见数/总数；无结果时清空关键词或点击重置。被隐藏的素材会取消选择，只有一个可见素材被选中时才能预览或替换。刷新当前工程保留筛选，切换工程重置筛选。
- **工作历史**：底部工作历史可搜索目标、工程名和详情，按 Agent 创作/手动修改/成片导出筛选，也可只看当前工程。选择有完整目标的记录后点“复用目标到当前工程”，会填入右侧 Agent 输入框；可以修改，再生成和审阅新方案。复用不会打开旧工程或执行旧方案。早期没有完整目标的记录仍可查看，不从截断标题猜测目标。
- **导入结果**：底部素材导入页逐项显示已导入、未完成、正在校验、等待导入以及真实错误。修复原路径文件后点“重试失败 / 继续未完成项”，只处理本批未成功文件；已成功素材保留。取消后可继续未完成项。新批次替换上一批结果，关闭/重新打开/切换工程清除恢复队列，应用重启不自动恢复导入。若原文件位置变化，可用导入或拖入选择新路径。

历史目标只复用文本；素材元数据、旧任务批准和旧任务范围不会自动复用。工作区最多保留 200 条历史与 12 个最近工程；历史序列化总量限制为 3 MiB，超过时淘汰最早记录。单条允许 64 KiB，以容纳合法目标的 JSON 转义；完整目标最多 8192 UTF-8 字节。恢复旧任务期间暂不可复用目标，恢复完成后可继续操作。
